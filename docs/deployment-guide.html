開始之前

這套系統由三個免費服務組合而成，各自負責一件事。你要做的，就是分別去申請，把它們給你的「一長串英文數字」貼到 Render，最後開啟網站。

服務負責什麼免費額度
GitHub存放程式碼，Render 從這裡讀取部署公開或私有儲存庫皆免費
Neon存放帳號、測驗成績、進度資料永久免費，資料不會過期
Render實際執行網站，並提供免費網址永久免費，閒置會休眠約 1 分鐘喚醒

先準備一個記事本

接下來會請你複製幾組長字串（連線字串、隨機密鑰）。建議先開一個記事本暫時貼著，最後一次貼到 Render。全部設定完成後，請把記事本刪掉。

整體流程圖

先看懂這張圖，後面每一步都只是在填其中一格。

0上傳到 GitHub

專案已經在本機用 git init 建好並 commit 完成，你只要建立一個空的 GitHub 儲存庫，把它接上去、推上去即可。這是全程唯一需要打指令的一步。

  1. 登入 github.com，點右上角 + → New repository。
  2. Repository name 輸入 iso26262-study-plan（或你喜歡的名稱）。
  3. Public 或 Private 皆可——這個專案沒有排程或 Actions，兩者都不影響費用。
  4. 下面三個選項都不要勾：Add a README file、Add .gitignore、Choose a license（本機專案已經有這些內容，勾了反而會衝突）。
  5. 點 Create repository，記下顯示的網址，例如 https://github.com/你的帳號/iso26262-study-plan.git。

回到本機的專案資料夾，執行以下兩行（把網址換成你剛剛記下的那一串）。在 Claude Code 裡可以直接在輸入框用 ! 開頭執行：

git remote add origin https://github.com/你的帳號/iso26262-study-plan.git git branch -M main git push -u origin main

✓ 這一步只需要做一次

程式上傳之後，日後要重新部署、改設定，全部都在網頁上完成，不需要再打指令（除非你要更新程式碼再推一次）。

1建立資料庫（Neon）

資料庫存放所有帳號與測驗成績。Neon 的免費方案資料不會過期。

  1. 打開 neon.com，按右上角的 Sign up，可以直接用 GitHub 帳號登入。
  2. 建立專案：名稱輸入 iso26262-study，其他保持預設，按 Create project。
  3. 畫面上會出現一段以 postgresql:// 開頭的長字串，標示為 Connection string。
  4. 複製它，貼到記事本，註明 DATABASE_URL。

它長這樣

postgresql://neondb_owner:········@ep-xxxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require

2建立網站主機（Render）

Render 負責實際執行系統，並提供一個 .onrender.com 的免費網址。因為專案裡已經有 render.yaml，Render 可以直接照著它把設定填好大半。

  1. 到 render.com 按 Get Started，用 GitHub 帳號登入並授權存取你剛剛建立的儲存庫。
  2. 按 New + → Blueprint，選擇 iso26262-study-plan 這個儲存庫。
  3. Render 會讀到 render.yaml，自動列出服務名稱 iso26262-study-plan 與需要你填寫的環境變數（因為都標記 sync: false，所以會請你手動輸入）。
  4. 先把看得到的欄位留白或填暫時值，按 Apply 建立服務。第一次啟動可能會失敗，這是正常的，下一步會回來把環境變數補齊。

3貼上四項設定

到剛剛建立的服務頁面，左側點 Environment，把記事本裡的東西貼進去。名稱必須一字不差，包含大小寫與底線。

名稱內容來源
DATABASE_URLNeon 連線字串步驟 1
SESSION_SECRET保護登入狀態的隨機字串自己產生
ADMIN_ID第一個管理者的登入 ID自己決定
ADMIN_INITIAL_PASSWORD管理者第一次登入的臨時密碼自己決定

隨機字串怎麼生？

SESSION_SECRET 只要夠長又難猜就好，你不需要記住它。隨手在鍵盤上打 40 個以上的英數字即可，例如 k8Fq2mZp7Lw4Rt9YvXb3Nc6Hd1Js5Gk0Aq2Wf8E。

✓ 填完按 Save，Render 會自動重新部署

存檔後 Render 會用新的環境變數重新啟動服務。等 1～2 分鐘，狀態變成綠色的 Live 就完成了。

4建立資料表與管理者帳號

網站啟動了，但資料庫裡還是空的。要跑一次 npm run migrate 來建立資料表，並依 ADMIN_* 建立第一個管理者帳號。

  1. 回到本機的專案資料夾，把 .env.example 複製一份成 .env。
  2. 打開 .env，把 DATABASE_URL、ADMIN_ID、ADMIN_INITIAL_PASSWORD 填成跟你剛剛貼到 Render 的完全一樣的值。
  3. 執行：
npm install npm run migrate
  1. 看到 已建立管理者帳號 的訊息就完成了。因為本機的 DATABASE_URL 跟 Render 上的指向同一個 Neon 資料庫，建好的表跟帳號 Render 那邊也看得到。

⚠ 這一步只需要做一次

之後不要重複執行 npm run migrate——腳本會偵測 ADMIN_ID 是否已存在，重複執行不會出錯，但也沒有必要。

5第一次登入

  1. 打開 Render 服務頁面最上方顯示的網址（例如 https://iso26262-study-plan.onrender.com）。第一次可能要等將近 1 分鐘，這是免費方案的喚醒時間。
  2. 用 ADMIN_ID 與 ADMIN_INITIAL_PASSWORD 登入。
  3. 系統會立刻要求你設定新密碼，請設定一組只有你知道的。

⚠ 為什麼一定要改密碼

初始密碼是明文存在 Render 的環境變數設定裡，因此系統強制你在第一次登入時更換，不改就無法使用任何功能。

6新增團隊成員

登入後點導覽列的成員管理，幫團隊成員建立帳號（ID、臨時密碼）。他們用臨時密碼登入後，一樣會被強制要求改成自己的密碼。

想掌握大家讀到哪，點導覽列的團隊進度，會看到每個人在每一圈的最新成績。

日後的操作

成員管理新增/查看團隊成員帳號，在網站上完成，不需要重新部署。
團隊進度看每位成員在每一圈的最新成績。
更新程式碼本機改完後 git push，Render 預設會自動偵測並重新部署。
Render → Logs網站出錯時，先來這裡看即時錯誤訊息。

重新部署（例如程式有更新）

git add -A git commit -m "更新內容" git push

Render 偵測到新的 commit 後會自動重新建置部署，不需要手動觸發。

常見問題

網站打開很慢，一直轉圈圈

免費方案在 15 分鐘沒人使用後會休眠，下一個人開啟時需要約 1 分鐘喚醒。喚醒後就恢復正常速度，這是正常現象。

部署失敗，Render 顯示紅色 Failed

點進該次部署看 Logs。最常見原因是環境變數缺少或名稱打錯，回到步驟 3 檢查四項設定的名稱是否完全一致（大小寫、底線）。

登入時顯示帳號或密碼不正確

確認 npm run migrate 已經成功執行過（步驟 4），且輸入的是 ADMIN_ID 與 ADMIN_INITIAL_PASSWORD 當初設定的值，注意大小寫。

忘記自己改過的密碼怎麼辦

目前版本沒有「忘記密碼」自助流程。請直接到 Neon 的 SQL Editor，把該帳號的 must_change_password 欄位改回 true，該使用者下次登入原本的臨時密碼仍能用（若也忘記臨時密碼，需要請管理者重新用同一個 ID 手動更新一筆 users 資料，或刪除後重建帳號）。

資料會不會不見

不會。Neon 免費方案不會刪除資料，所有測驗紀錄與帳號都會保留。

想加新的一圈學習內容怎麼辦

這是設計上就支援的：在 public/circles/ 新增一個 circle-0X-xxx.html，在 public/assets/data/ 新增對應的 circle-0X.quiz.js，並在 public/assets/data/circles.js 與 server/circles.js 各加一筆設定，重新 git push 即可，不需要更動資料庫結構。
