自架部署手冊 ・ v1.0

在 Ubuntu 上架設 ISO 26262 學習網站

整套跑在你自己的 Ubuntu 機器上，資料庫也在同一台，不需要任何雲端服務、不需要對外網路。

  • 所需時間 約 25 分鐘
  • 費用 NT$0
  • 需要 sudo 權限
  • 對外網路 只有下載套件時需要

開始之前

這份手冊跟 Render 部署手冊 是兩條互斥的路：那一份把網站放上雲端，這一份把整套東西架在你自己的 Ubuntu 機器上。兩者的程式碼完全相同，差別只在資料庫在哪裡、由誰負責把服務叫起來。

元件負責什麼這份手冊怎麼裝
Node.js執行 Express 網站程式apt 安裝（需 18 以上）
PostgreSQL存放帳號、測驗成績、session裝在同一台機器，走 localhost
systemd開機自動啟動、當掉自動重開Ubuntu 內建，寫一個 service 檔

✓ 為什麼自架比雲端單純

資料庫就在 localhost，不經過任何對外連線，所以公司 proxy、防火牆擋 5432 這類問題全部不存在。裝完之後整套可以完全離線運作。

你需要先知道的一件事

這個網站沒有自助註冊功能。第一個管理者帳號是在步驟 4 由環境變數建立的，之後其他成員都要由管理者在網站上新增。這是刻意的設計，不是還沒做完。

整體架構圖

全部在同一台機器上，沒有跨機器的連線。

0安裝 Node.js

專案需要 Node.js 18 以上。先看看機器上有沒有，有的話就跳過這步。

node -v

如果指令找不到，或版本低於 18，用 Ubuntu 內建的套件庫裝：

sudo apt update sudo apt install -y nodejs npm node -v

⚠ 如果 apt 裝出來的版本低於 18

比較舊的 Ubuntu（22.04 以前）套件庫裡的 Node 可能太舊。改用 NodeSource 的套件庫裝 20：

curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash - sudo apt install -y nodejs node -v

1安裝 PostgreSQL 並建立資料庫

資料庫跟網站放在同一台機器，走 localhost，不對外開放。

sudo apt install -y postgresql sudo systemctl enable --now postgresql systemctl status postgresql --no-pager

看到 active (running) 就代表資料庫服務起來了。

建立專用的資料庫與使用者

不要用 postgres 超級使用者來跑網站。建立一組專用帳號：

sudo -u postgres psql

進到 postgres=# 提示字元後，依序貼上這三行（密碼請改成你自己的）：

CREATE USER iso26262 WITH PASSWORD '換成你自己的密碼'; CREATE DATABASE iso26262 OWNER iso26262; \q

記下你的連線字串

照上面建立的話，連線字串就是：

postgresql://iso26262:你的密碼@localhost:5432/iso26262

下一步會用到。注意結尾沒有 ?sslmode=require——本機資料庫預設沒開 SSL，程式會自動判斷不要用 SSL 連。

2取得程式碼

從 GitHub 抓下來，並安裝相依套件。

cd ~ git clone https://github.com/你的帳號/iso26262-study-plan.git cd iso26262-study-plan npm install

npm install 需要對外網路（要從 npm 下載套件）。裝完之後，整套就不再需要對外連線了。

3建立 .env

環境變數決定資料庫接哪裡、第一個管理者帳號是誰。

cp .env.example .env nano .env

把四個值填成你自己的：

名稱填什麼來源
DATABASE_URLpostgresql://iso26262:你的密碼@localhost:5432/iso26262步驟 1
SESSION_SECRET隨手打 40 個以上的英數字，不用記住自己產生
ADMIN_ID你要用來登入的 ID，也會顯示在頁首自己決定
ADMIN_INITIAL_PASSWORD第一次登入用的臨時密碼自己決定

另外把 NODE_ENV 設成 production，PORT 保持 3000 即可。在 nano 裡按 Ctrl+O 存檔、Ctrl+X 離開。

⚠ .env 不會進版控，也不該進版控

.gitignore 已經排除 .env。這代表你在每一台部署的機器上都要自己建一份，也代表不要把密碼貼到 git 或聊天訊息裡。

4建立資料表與管理者帳號

資料庫現在還是空的，跑一次 migration 把資料表和第一個管理者建出來。

npm run migrate

成功的話會看到：

執行 schema.sql 建立資料表... 資料表建立完成。 已建立管理者帳號：你填的 ID（第一次登入會強制要求改密碼） Migration 完成。

✓ 這一步只需要做一次

腳本會偵測管理者 ID 是否已存在，重複執行不會出錯也不會重複建立，但沒有必要。

5先手動跑一次

在寫 systemd 設定之前，先確認它真的能跑起來。

npm start

看到 ISO 26262 學習網站啟動於 http://localhost:3000 就對了。另外開一個終端機測試：

curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3000/login.html

回 200 代表網站活著。如果這台機器有桌面環境，直接用瀏覽器開 http://localhost:3000 就會看到登入頁。確認完按 Ctrl+C 停掉，接著設成常駐服務。

6設成開機自動啟動

用 systemd 管理，機器重開之後網站會自己起來，程式當掉也會自動重啟。

  1. 先確認兩件事，等一下要填進設定檔：
    whoami pwd which node
  2. 建立 service 檔：
    sudo nano /etc/systemd/system/iso26262.service
  3. 貼上以下內容，把 你的帳號 與兩個路徑換成上一步查到的實際值：
    [Unit] Description=ISO 26262 學習網站 After=network.target postgresql.service [Service] Type=simple User=你的帳號 WorkingDirectory=/home/你的帳號/iso26262-study-plan ExecStart=/usr/bin/node server/index.js Restart=on-failure RestartSec=5 Environment=NODE_ENV=production [Install] WantedBy=multi-user.target
  4. 存檔離開，然後啟用：
    sudo systemctl daemon-reload sudo systemctl enable --now iso26262 systemctl status iso26262 --no-pager
  5. 看到 active (running) 就完成了。

為什麼 ExecStart 要寫絕對路徑

systemd 不會載入你的 shell 設定，所以 node 不一定在它的 PATH 裡。用 which node 查到的絕對路徑最保險。如果你是用 nvm 裝的 Node，路徑會長得像 /home/你的帳號/.nvm/versions/node/v20.x.x/bin/node。

⚠ 服務起不來的話

systemctl status 只會顯示最後幾行。看完整錯誤訊息用：

journalctl -u iso26262 -n 50 --no-pager

最常見的原因是 WorkingDirectory 路徑打錯，或 .env 不在那個目錄底下。

7讓區網其他機器連得到

如果只在這台機器上看，這步可以跳過。要讓同事或你另一台電腦連進來，才需要開防火牆。

先查這台機器的區網 IP：

hostname -I

如果有啟用 ufw，放行 3000 埠：

sudo ufw allow 3000/tcp sudo ufw status

然後在別台機器的瀏覽器輸入 http://那個IP:3000 就能連上。

⚠ 這是 HTTP，不是 HTTPS

密碼會以明文在區網上傳輸。放在公司內網的信任環境還可以接受，但不要把 3000 埠轉發到公開網際網路。真的需要對外，請改用 Render 部署（自帶 HTTPS），或在前面架一層 nginx + Let's Encrypt 憑證。

不要開放 5432

資料庫沒有任何理由需要被區網其他機器連到。維持預設的只聽 localhost 就好。

備份資料庫

帳號與所有測驗成績都在資料庫裡，程式碼在 git 上，所以要備份的只有資料庫：

pg_dump -U iso26262 -h localhost iso26262 > ~/iso26262-backup-$(date +%F).sql

還原：

psql -U iso26262 -h localhost iso26262 < ~/iso26262-backup-2026-09-10.sql

完整移除

把這個網站從機器上徹底清掉，包含資料。四個部分彼此獨立，照順序做即可。

⚠ 資料刪掉就沒了

所有帳號與測驗成績都在資料庫裡，刪掉之後沒有任何辦法救回來。就算只有一點點懷疑之後可能還要用，先做一份備份再往下走——備份檔很小，留著幾乎不佔空間：

pg_dump -U iso26262 -h localhost iso26262 > ~/iso26262-final-backup.sql

1. 停止並移除服務

先停服務，否則資料庫還有連線，下一步會刪不掉。

sudo systemctl stop iso26262 sudo systemctl disable iso26262 sudo rm -f /etc/systemd/system/iso26262.service sudo systemctl daemon-reload sudo systemctl reset-failed

2. 刪除資料庫與資料庫使用者

順序不能反——角色是資料庫的擁有者，資料庫還在的時候刪不掉角色。

sudo -u postgres psql -c "DROP DATABASE IF EXISTS iso26262;" sudo -u postgres psql -c "DROP ROLE IF EXISTS iso26262;"

如果出現 database "iso26262" is being accessed by other users，代表還有連線沒斷。確認第 1 步的服務真的停了，也確認自己沒有開著 psql 連在上面。

3. 刪除程式碼

sudo rm -rf ~/iso26262-study-plan

裝在別的位置就換成該路徑，例如 /opt/iso26262-study-plan。執行前先看清楚路徑，rm -rf 打錯不會問你第二次。

4. 收回防火牆規則

只有當初為了讓區網連入而開過埠才需要做。埠號換成你實際用的那個。

sudo ufw delete allow 3000/tcp

要不要順便移除 PostgreSQL 和 Node.js？

⚠ 先確認沒有別人在用，再決定

這兩個是共用的系統套件，不是這個網站專屬的。直接 apt purge 很可能弄壞這台機器上的其他服務——監控系統、其他網站、排程工具都可能依賴它們。

先看資料庫裡還有沒有別人的東西。除了 postgres、template0、template1 這三個內建的以外，還有其他資料庫就不要移除 PostgreSQL：

sudo -u postgres psql -c "\l"

再看還有沒有別的程式在用 Node：

ps aux | grep -v grep | grep node

兩邊都確認乾淨、而且你確定這台機器不再需要它們，才執行移除：

sudo apt purge -y postgresql postgresql-* sudo apt purge -y nodejs npm sudo apt autoremove -y

只要有一絲不確定，就把這兩個留著。它們閒置時幾乎不耗資源，留著的代價遠低於弄壞別的服務。

常見問題

npm run migrate 出現 ECONNREFUSED 127.0.0.1:5432

PostgreSQL 沒在跑。用 sudo systemctl status postgresql 確認，必要時 sudo systemctl start postgresql。

出現 The server does not support SSL connections

代表你的 DATABASE_URL 結尾帶了 ?sslmode=require，但本機 PostgreSQL 沒開 SSL。把那段參數拿掉即可——本機連線不需要 SSL。

出現 password authentication failed for user "iso26262"

.env 裡的密碼跟步驟 1 建立使用者時設的不一致。可以重設：sudo -u postgres psql -c "ALTER USER iso26262 WITH PASSWORD '新密碼';"，然後同步改 .env。

登入時顯示帳號或密碼不正確

先確認 npm run migrate 有成功跑過（步驟 4）。登入要用的是 ADMIN_ID 與 ADMIN_INITIAL_PASSWORD，注意大小寫。改過密碼之後就要用新密碼。

忘記密碼了

目前沒有自助重設流程。直接連進資料庫把該帳號標記成需要改密碼，下次登入時用臨時密碼進去即可：

psql -U iso26262 -h localhost iso26262 -c "UPDATE users SET must_change_password = true WHERE login_id = '該成員的ID';"

如果連臨時密碼也忘了，最乾脆的做法是刪掉該帳號重建（管理者帳號可以改 .env 後重跑 migrate）。

npm start 出現 EADDRINUSE: address already in use :::3000

代表 3000 埠已經有程式在聽了。先查是誰：

sudo ss -ltnp | grep :3000

最常見的原因是網站已經在跑了。如果你已經做完步驟 6，systemd 就會一直把它拉著，這時候不需要也不應該再手動 npm start——直接開瀏覽器就好。用 systemctl status iso26262 確認，看到 active (running) 就是正常的。

如果佔用的是別的程式（Grafana 預設就是 3000），那就改用其他埠。先確認要換的埠沒人用——下面這行沒有輸出才代表可用：

sudo ss -ltnp | grep :3200

確認可用後，編輯 .env 把 PORT 改成 3200，再 sudo systemctl restart iso26262（還沒設 systemd 的話就直接 npm start），網址跟著換成 :3200。防火牆若開過 3000，記得改開新的埠。

⚠ 別挑 3100

Grafana Loki 預設用 3100。如果這台跑的是 Grafana 全套，挑 3100 只會換一個對象再撞一次。

重開機之後網站沒起來

確認服務有被 enable：systemctl is-enabled iso26262 應該回 enabled。如果回 disabled，執行 sudo systemctl enable iso26262。

這台機器可以同時跑 Render 版本嗎？

可以，兩者互不影響，但它們是各自獨立的資料庫——在自架版做的測驗成績不會出現在 Render 版，反之亦然。建議挑一邊當正式使用，另一邊當測試。
